**Завдання для ЛЛМ: реалізація pipeline генерації документів**

---

**Загальний опис**

Python-додаток з HTML-інтерфейсом для генерації .docx документів на основі структури шаблону та джерел даних. Підтримує два режими роботи: повний документ або через векторний пошук по чанках.

---

**Технічний стек**

```
Backend:     Python, Flask
Frontend:    один HTML файл (налаштування + запуск)
LLM:         універсальний клієнт з вибором провайдера
Векторна БД: ChromaDB (локально)
Embedding:   nomic-embed-text через Ollama (локально, CPU)
Документи:   pdfplumber (PDF), python-docx (docx), вбудований (txt)
Вихід:       python-docx
```

---

**Модуль extractor.py**

Витягує plain text з будь-якого вхідного файлу. Підтримує PDF (pdfplumber), docx (python-docx), txt/md (вбудований). Повертає рядок тексту та метадані (назва файлу, кількість сторінок/слів).

---

**Модуль chunker.py**

Два режими що обирає користувач:

Режим `fixed` — розбиття по фіксованій кількості слів:
```
параметри: chunk_size (100-1000 слів), overlap (0-200 слів)
алгоритм: sliding window по словах
```

Режим `paragraph` — розбиття по абзацах:
```
параметри: min_chunk_size (мін. слів щоб не створювати мікрочанки), 
           merge_threshold (якщо абзац менший — злити з наступним)
алгоритм: розбити по \n\n, злити короткі, зберегти межі абзаців
```

Кожен чанк зберігає: `{text, source_file, chunk_index, word_count}`

---

**Модуль vectorstore.py**

Операції з ChromaDB:
- `build(chunks, collection_name)` — створити/перебудувати колекцію
- `search(query, top_k, threshold)` — пошук з фільтром по score
- `exists(collection_name)` — перевірити чи база вже побудована
- `clear(collection_name)` — очистити

Параметр `threshold` (0.0-1.0) — мінімальна cosine similarity для включення чанку у результат. Налаштовується користувачем як "точність пошуку".

---

**Модуль llm_client.py**

Універсальний клієнт з підтримкою провайдерів:
- Anthropic (claude-*)
- OpenAI (gpt-*)
- Ollama (локальні моделі)
- OpenRouter (будь-яка модель через єдиний endpoint)

Інтерфейс однаковий для всіх:
```python
client.complete(system_prompt, user_prompt, max_tokens) → str
```

API ключі та endpoint зберігаються в settings.json.

---

**Pipeline — режим FULL (повний документ)**

```
1. extractor: всі джерела → об'єднаний текст
2. analyzer:  шаблон → структура (промпт аналізу)
3. generator: структура + повний текст джерел → згенерований текст
4. docx_writer: текст → output.docx
```

---

**Pipeline — режим CHUNKS (через векторний пошук)**

```
1. extractor:      всі джерела → тексти
2. chunker:        тексти → чанки (fixed або paragraph)
3. vectorstore:    чанки → ChromaDB колекція
4. analyzer:       шаблон → структура
5. query_builder:  структура → підзапити (один на розділ) [LLM запит 1]
6. vectorstore:    підзапити → релевантні чанки (top_k, threshold)
   дедублікація:   один пул унікальних чанків для всього документа
7. generator:      структура + відібрані чанки → документ [LLM запит 2]
8. docx_writer:    текст → output.docx
```

**HTML сторінка — розділи**

```
[Провайдер та модель]
  - вибір провайдера (dropdown)
  - API key (input, зберігається локально)
  - назва моделі (input)
  - кнопка "Перевірити з'єднання"

[Джерела]
  - multiple file upload (PDF, docx, txt)
  - шаблон (окремий upload)

[Режим роботи]
  - radio: Повний документ / Через чанки

[Налаштування чанків] (показується якщо режим = Chunks)
  - тип: fixed / paragraph
  - chunk_size (slider 100-1000, default 400)
  - overlap (slider 0-200, default 75) — тільки для fixed
  - min_chunk_size (slider 50-300, default 100) — тільки для paragraph
  - точність пошуку threshold (slider 0.0-1.0, default 0.7)
  - top_k чанків на розділ (slider 1-5, default 2)

[Запуск]
  - кнопка "Згенерувати"
  - прогрес-бар з поточним кроком
  - лог виконання (текстове поле)
  - кнопка "Завантажити результат" (після завершення)
```

---

**Додаткові вимоги**

- Всі налаштування зберігаються в `settings.json` і відновлюються при наступному відкритті
- Якщо ChromaDB колекція для цих самих файлів вже існує — не перебудовувати (кешування по хешу файлів)
- Логування кожного кроку в UI в реальному часі через SSE (Server-Sent Events)
- Якщо генерація розділу повернула менше ніж `min_words * 0.7` — автоматично повторити запит один раз
- Вихідний файл: `output/[назва_шаблону]_[дата].docx`
