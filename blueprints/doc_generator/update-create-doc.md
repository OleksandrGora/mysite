Оновлення.
По дизайну. Титульна сторінка буде мати тільки перелік завдань та кнопку Створити завдання.
Створення завдання буде на окремій сторінці - модальному вікні.
На цю сторінку переносяться поле: поле для вводу промпта (вище за вибір файлу шаблону), вибору файла шаблона, аналіз файла шаблона, вибір файлів джерел, кнопка формування фінального документа.
На сторінку додається поле для виводу аналіза та можливості редагування аналізу. ТОбто, є результат аналізу, його можна тут же відредагувати (це просто текстове поле, без ніяких інструментів), зберегти у файл. Поле для вводу промпту, поле для вибору файла для аналізу, кнопку Аналіз візуально згрупувати, обвести.
Є окрема група (також обведена візуально), де знаходяться поле для промпту для формування фінального документа, поле для вибору джерел, кнопка запуску фінального формування. Фінальний документ теж зберігаєтьяс на диску сервера.

Архітектура сервера. Додається функціонал збереження документів на сервері.
Створюється папка Tasks-data. Всередині папки при створенні завдання під кожне завдання створюється окрема папка з ім'ям завдання. Імʼя береться з імені файла шаблона. Якщо така папка є - додаяться просто цифра через пробіл. Папка створюється у момент натискання аналізу, коли відомо імʼя джерела.
У папці зберігаються: файл з аналізом (згаданий вище), фінальнй документ (згаданий вище), файл task-info.json з налаштуваннями завдання як json: статус завдання (proceccing, completed, failed), промпти для аналізу та формування фінального документа, вибрані файли шаблону та джерел.
Робота з файлами. При виборі документа для шаблону чи джерел, файли вантажаться у папки відповідно Templates та Sources. При спробі вибрати файл шаблону чи джерела, є можливість як підвантажити локальні файли (з компʼютера користувача), так і вибрати існуючі файли у буль-якій папці незалежно чи вибираємо шаблон чи джерело. У файлі task-info.json зберігаються посилання на файли шаблона та джерел, оскільки все завантажене на сервер.
Модаьне вікно завдання можна закрити у будь який момент. Вже внесена інформація зберігається на сервері. Якщо запущений аналіз чи формування фінального документа, закриття вікна не повинно переривати процес, все повинно працювати асинхронно.

При видаленні задачі з інтерфейсу програми папка, яка відноситься до задачі видаляється.

Зміна у логіці аналізу. При виборі файлу аналіз відразу запускається на ллм моделі. Етап проміжного конвертування файлу локально видаляємо. Логіка аналізу, програмний промпт залишається як є.

Поле Дебаг. Повинно бути доступне для модального вікна завдання. Коли завдання відкрите та працює, там повинна виводитися інформація про повідомлення у функціях обробки завдання.

При завантаження сторінки для аналізу (просто корисувач заходить на сторінку), програма завантажує перелік завдань та статуси з папки Tasks-data. Це єдине джерело збереження інформації по завданнях. Це не потрібно зберігати улокальному сховищі сервера. Перелік завдань, інформація по них повинна бути доступна для будь якого користувача, для будь якого сеансу.
